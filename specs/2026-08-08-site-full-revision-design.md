# サイト全面改定 デザイン文書

日付: 2026-08-08
ブランチ: `docs/full-revision`

## 背景と目的

現行サイト（`docs/`、MkDocs Material、19章+付録2）は「Python と PostgreSQL の基礎をひととおり学んだ人」を想定していた。
新しい対象読者は以下に変わる。

- Python の文法（変数・関数・条件分岐・ループ・クラス・import）は理解している
- **実用プログラムを書いたことはない**（パッケージ管理、仮想環境、サーバー、HTTP などの実践概念は未経験）
- SQL は一度習ったが**だいぶ忘れている**

目的: 読者が自分の手で FastAPI + PostgreSQL の ToDo アプリを写経して完成させ、「壊れたときに自分で原因を追える」状態になること。

## スコープ

- **対象**: `docs/` 配下の全 21 ファイル（index、第0〜18章、付録A/B）
- **非対象**: `sample/todo-app/` のコードは変更しない。章のコード片は完成版と一致させる
- 章立て（19章+付録2、7つのPart）と技術スタック（psycopg3 生SQL / FastAPI / Jinja2 / htmx / pytest / uv / Docker）は維持

## 決定事項（ブレインストーミング結果）

| 論点 | 決定 |
|---|---|
| 対象範囲 | `docs/` のみ。`sample/todo-app` は完成版参照先として据え置き |
| 改定の方向性 | 前提知識の補強 / 手順の完全再現性 / SQLリハビリ強化 / 練習問題の充実（全部） |
| コードの扱い | 実装パート（第10〜16章）は写経式。読者は自分の作業ディレクトリでファイルを作り写す |
| 進め方 | 全 21 ファイルのフルリライト |

## 全章統一フォーマット

各章は以下の構成で書き直す（内容が不要な章だけ省略可、順序は固定）。

1. **この章でやること** — ゴールと所要時間の目安を明示
2. **前提知識** — 実践未経験者が躓く概念（サーバー/クライアント、HTTP、プロセス、ポート、仮想環境、ドライバ等）を、その章で使う分だけ `!!! note` 等で解説
3. **手順** — コマンドと**期待される出力**を必ずセットで記載
4. **チェックポイント** — 「ここまでできたか」の確認リスト（tasklist）
5. **つまずきポイント** — よくあるエラーと対処法
6. **やってみよう** — 段階的な練習問題＋解答例（details/summary で折りたたみ）
7. **まとめ** — 学んだことの箇条書きと次章への橋渡し

## 章別の改定方針

### index.md
- 想定読者を新ターゲットに書き換え
- 「読む前にわかっていること / わからなくてよいこと」を明確化
- スケジュール表は維持しつつ、各回の目安時間を初学者ペースに調整

### 第0章 環境構築（00-setup.md）
- Docker・uv・仮想環境の概念説明から入る（「なぜ必要か」レベルから）
- 全コマンドに期待出力を記載
- トラブルシューティングを拡充（ポート競合、Docker が動かない、uv が見つからない等）

### 第1〜2章 Python（01, 02）
- 文法の復習はしない。「実践で使うが入門書には載っていない」ものに絞る
  - 第1章: 型ヒント・dataclass（なぜ使うか、から）
  - 第2章: with 文・モジュール分割・pytest
- いずれも「書いたことがない」前提で、実行例と期待出力つき
- 練習問題を増量（解答例つき）

### 第3〜4章 PostgreSQL（03, 04）
- 「思い出す」前提をやめ「ほぼ初めて」前提に書き直す
- psql の起動・終了・基本メタコマンド（`\dt` 等）から記載
- 全 SQL に実行結果の表示例を記載
- 表の図解（before/after の表形式）を増やす
- 練習問題を増量（解答例つき）

### 第5〜7章 psycopg（05, 06, 07）
- クライアント/サーバーモデル、ドライバ、コネクション、カーソル、コネクションプールの概念を図解レベルで丁寧に
- SQL インジェクションの説明は維持しつつ、初心者向けに平易化
- 手順と期待出力を完備

### 第8〜9章 設計（08, 09）
- 「なぜ設計してから書くのか」を初学者向けに補強
- 要件→画面→API→テーブルの流れは維持
- ここで作るものの完成形と、写経の進め方（`mytodo/` を作る）を明示

### 第10〜16章 アプリ構築（10〜16）— 写経式
- 読者は自分の作業ディレクトリ `mytodo/`（`sample/todo-app` とは別）にファイルを新規作成して写経
- コードは**全文掲載**（「以下略」は使わない）
- 各章の冒頭に「ここまでのファイル構成」ツリー、末尾に動作確認手順と期待出力
- 詰まったときの案内: `diff -ru mytodo/ sample/todo-app/` での差分確認
- `sample/todo-app` は「答え合わせ用の完成版」と明記

### 第17〜18章 仕上げ（17, 18）
- 設定管理・ログ・例外ハンドリングの概念を初学者向けに補強
- デプロイ選択肢の説明は維持、手順の再現性を強化

### 付録A SQLチートシート / 付録B 用語集
- 付録A: 実行例つきに拡充（忘れた人が引き直せるように）
- 付録B: HTTP、ポート、プロセス、仮想環境、ORM、DSN など実践未経験者向けの語彙を追加

## 検証

1. `uv run mkdocs build --strict` が成功すること（CI と同じ条件）
2. 写経用コード片が `sample/todo-app` の完成版と矛盾しないこと（写経後に `diff` で一致確認できるレベル）
3. 各章が統一フォーマットに従っていること
