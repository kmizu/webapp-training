# はじめに

このテキストは、**Python の文法は知っているけれど、まだ実用プログラムを書いたことがない人**が、
手を動かして小さな ToDo アプリ（Web アプリ）を完成させるための研修教材です。

文法の入門書を終えて「次に何を書けばいいのか」で止まっている人、
SQL は習ったはずなのに `JOIN` が出てくると自信がない人を想定しています。
そういう人でも、このテキストの手順どおりに進めれば、
FastAPI + PostgreSQL の ToDo アプリを**自分の手で写して、動かして、壊したときに直せる**ところまで到達できます。

## 読む前にわかっていること

次の内容は既知として進めます。自信がなければ、先に入門書やチュートリアルで確認しておいてください。

- Python の基本文法（変数、関数、条件分岐、ループ、クラス、`import`）
- ターミナル（コマンドプロンプト）でコマンドを打つこと自体に抵抗がない
- SQL を一度は学んだことがある（忘れているのは問題ありません）

## わからなくてよいこと（このテキストで説明します）

逆に、次のことは**知らない前提で説明**します。知らなくても心配いりません。

- 仮想環境やパッケージ管理（`uv`）の使い方
- Docker で PostgreSQL を立てる方法
- SQL の細かい文法（第3〜4章と付録Aで思い出せる構成にしています）
- Python とデータベースをつなぐ仕組み（ドライバ、コネクション、プール）
- Web の仕組み（HTTP、サーバーとクライアント、ポート）の実務的なところ
- Web フレームワーク（FastAPI）、テンプレート（Jinja2）、htmx の使い方
- テスト（pytest）の書き方

## このテキストで作るもの

- ターミナルで PostgreSQL に接続して操作できる小さな Python プログラム
- それをベースにした **ToDo アプリの Web 版**（FastAPI + Jinja2 + htmx）
- データを 1 件ずつしっかり追跡できる、最小限だが完結した実装

完成イメージはこんな感じです。

```text
+-----------------------------------------------+
|  ToDo                                         |
+-----------------------------------------------+
|  [ ] 牛乳を買う           期限: 5/8           |
|  [x] 健康診断の予約       完了                |
|  [ ] 領収書の整理         期限: 5/10  優先=高 |
+-----------------------------------------------+
| [ + 追加 ]                                    |
+-----------------------------------------------+
```

派手さはありません。代わりに **「データがどこに、どう保存されているのか」
「Python と DB の間を何が行き来しているのか」** が読めばわかる構成にしています。

## 進め方

19 章 + 付録 2 を **7 つの Part** に分けています。
実践がはじめての人でも詰まらないよう、**1 章 = 45〜90 分**で読み切れる量にしてあり、
**1 セッション = 1 章** くらいのペースを想定しています。

| Part | 内容 | 章 |
|---|---|---|
| 1 | 復習と基礎固め（Python と PostgreSQL のおさらい） | 第0〜4章 |
| 2 | Python と DB をつなぐ（psycopg） | 第5〜7章 |
| 3 | ToDoアプリの設計（要件・画面・API・テーブル） | 第8〜9章 |
| 4 | データアクセス層（Repository とテスト） | 第10〜12章 |
| 5 | Web API（FastAPI） | 第13〜14章 |
| 6 | 画面（Jinja2 + htmx） | 第15〜16章 |
| 7 | 仕上げ（設定・ログ・例外・公開先） | 第17〜18章 |

第 1〜2 章（Python）は「文法は知っている」前提で、入門書に載らない実践的な話題
（型ヒント、dataclass、`with` 文、モジュール分割、pytest）だけを扱います。
第 3〜4 章（PostgreSQL）は「忘れてしまった」前提で、psql の起動から丁寧にやり直します。

### 写経で進めます

第 10 章以降のアプリ構築パートは**写経式**です。

- 自分の作業ディレクトリ `mytodo/` に、ファイルを 1 つずつ新規作成して写します
- コードは**全文掲載**しているので、迷うことはありません
- リポジトリ内の `sample/todo-app/` は**答え合わせ用の完成版**です。
  動かないときは `diff -ru mytodo/ sample/todo-app/` で差分を確認してください

写経は非効率に見えるかもしれませんが、
「自分で打ったコードしか、壊れたときに直せない」のが実情です。
コピー＆ペーストではなく、必ず自分で打ってください。

各章の末尾には「**やってみよう**」という練習問題があります（解答例つき）。
読むだけでなく、できれば必ず手を動かしてください。

## 使う道具

| 種類 | 使うもの | 備考 |
|---|---|---|
| 言語 | Python 3.12+ | 型ヒントとデータクラスを活用 |
| パッケージ管理 | [uv](https://docs.astral.sh/uv/) | `pip` の代わり。速くて壊れにくい |
| DB | PostgreSQL 16 | Docker で立てる（第0章で手順どおりに） |
| DB ドライバ | [psycopg](https://www.psycopg.org/psycopg3/) v3 | 生 SQL を書く方針 |
| Web | [FastAPI](https://fastapi.tiangolo.com/) | 型ヒントベースで小さい |
| テンプレート | Jinja2 | サーバーで HTML を組み立てる |
| 動的UI | [htmx](https://htmx.org/) | JavaScript をほぼ書かずに非同期更新 |
| テスト | pytest | データ層と API に最低限のテストを書く |

!!! tip "ORM は使いません"
    SQLAlchemy のような ORM もよい選択肢ですが、本研修では
    **「SQL がそのまま見える状態」** を維持するために生 SQL を書きます。
    SQL を忘れかけている人にとっては、むしろこの方が復習になります。

## 心がけ

このテキストを読みながら、つねに次の問いを意識してください。

1. **データはどこに置いているか**（メモリ？ DB？ ブラウザ？）
2. **誰がそのデータを書くのか / 読むのか**
3. **失敗したらどうなるか**（接続が切れた、DB が落ちた、入力がおかしい）

きれいに動くコードを書くより、
**「壊れたときに自分で原因を追える」** ようになることのほうがずっと大切です。
エラーメッセージは敵ではなく、原因への道しるべです。各章の「つまずきポイント」も
その練習の一部だと思って読んでください。

それでは、[第 0 章 環境構築](00-setup.md) から始めましょう。
